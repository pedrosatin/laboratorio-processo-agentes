Cenário fixo · 5 min

1. O que aconteceu

Uma equipe pediu a função filtrarTarefas. Montou um processo com três agentes e rodou uma vez. Os testes do tester e os testes de referência passaram. A entrega foi reprovada pelo gate de rastreabilidade do cliente.

Tester 5/5 · Referência 7/7 · Gate rastreabilidade reprovado · Encerramento: reprovado

O pedido do cliente e a política do projeto pediam identificadores nos critérios e nos testes. Os agentes produziram comportamento correto e rastreabilidade incorreta.

Pedido

Implemente filtrarTarefas(tarefas, filtro).
Estados aceitos: todas, abertas, concluidas.
O filtro por termo busca no título.
Estado inválido deve lançar erro com a mensagem "Estado inválido".
Preserve a ordem e os objetos recebidos.

Política que os agentes deveriam seguir

# Política de rastreabilidade do projeto

1. Cada critério de aceite começa com um ID no formato C1, C2, C3, sem repetição.
2. A especificação tem no máximo cinco critérios.
3. O campo criterio de cada caso de teste começa com o ID do critério que o caso verifica.
4. Todo critério tem pelo menos um caso de teste.
5. A matriz critério, caso e resultado acompanha a entrega.

Essa política estava disponível como material do projeto. Na execução registrada, o agente spec não a recebeu nas instruções de usuário. O tester também não foi instruído a citar os IDs.

Critérios produzidos pelo spec

1. Deve retornar todas as tarefas quando o estado for 'todas' e não houver termo
2. Deve retornar apenas tarefas abertas (concluida === false) quando o estado for 'abertas'
3. Deve retornar apenas tarefas concluidas (concluida === true) quando o estado for 'concluidas'
4. Deve lançar um erro com a mensagem 'Estado inválido' caso o estado seja desconhecido
5. Deve filtrar as tarefas cujo título contenha o termo fornecido
6. Deve ignorar o filtro de termo caso este seja indefinido, vazio ou só espaços
7. Deve manter a ordem original das tarefas da lista recebida

Casos produzidos pelo tester

filtrarTodasSemTermo  — criterio: "retorna todas sem termo"
filtrarAbertas        — criterio: "retorna só abertas"
filtrarPorTermo       — criterio: "filtra pelo termo no título"
estadoInvalidoErro    — criterio: "erro em estado inválido"
ignorarTermoBranco    — criterio: "ignora termo em branco"

Detalhes do gate

  • Critérios sem ID no início (C1, C2…).
  • O spec entregou 7 critérios; a política limita a 5.
  • Os cinco casos do tester não citam um ID de critério existente.
Lembrete rápido: verificação e validação

Os casos do tester conferem o código contra a especificação. Isso é verificação.

Os testes de referência conferem o código contra o pedido original. Isso é validação.

O gate confere regras de processo do cenário. Aqui ele falhou mesmo com verificação e validação aprovadas.
