O que você vai investigar

Regras do projeto, decisões dos agentes

Você vai trabalhar com três agentes de IA já montados no Dify. Cada um tem uma tarefa:

  • O spec lê o pedido e escreve o que o código precisa fazer.
  • O coder escreve o código a partir dessa descrição.
  • O tester escreve cinco testes para conferir o código.

Seu cenário traz regras de uma equipe. Você vai decidir o que acrescentar às instruções de cada agente e quais materiais ele precisa receber.

Primeiro, execute tudo como está. Depois, faça as alterações e execute de novo. O verificador desta página testa o resultado e mostra o que passou e o que falhou.

Preparação · 15 min

2. Preparar o Dify

O Dify organiza os agentes em um fluxo, chamado workflow. Cada bloco desse fluxo é um nó. Você vai importar um arquivo com os blocos já montados.

  1. Abra cloud.dify.ai e entre com GitHub ou Google. O plano Sandbox é gratuito e não pede cartão.
  2. Baixe o arquivo do fluxo: a8-spec-coder-tester.yml.
  3. No Studio, clique em Importar DSL (Import DSL file) e selecione o arquivo baixado. DSL é o nome que o Dify usa para esse arquivo de configuração.
  4. Se aparecer um pedido para instalar o plugin OpenAI, instale. Esse complemento permite usar o modelo no Dify.
  5. Clique em cada bloco dos agentes spec, coder e tester. Confira se o modelo escolhido é gpt-4o-mini. O modelo é a IA que responde ao agente. Ele usa os créditos gratuitos do Dify.
  6. Confira os blocos na imagem abaixo. Depois do spec, os blocos Ler especificação e Tem dúvidas? conferem se ele deixou perguntas. Se houver dúvidas, o fluxo para. Caso contrário, tester e coder recebem a descrição do spec, chamada especificação. O bloco Montar entrega reúne as respostas.

Como ler o resultado
    
Os casos do tester são os cinco testes escritos pelo agente. Eles conferem se o código cumpre a especificação. Essa é a verificação.

    
A suíte de referência é um conjunto de sete testes preparados a partir do pedido original. Os agentes não veem esses testes. Eles conferem se o código atende ao pedido. Essa é a validação.

    
O gate é a checagem das regras do seu cenário, como o limite de linhas alteradas. Ele sempre dá o mesmo resultado para a mesma entrada. Já o agente pode responder de outro jeito a cada execução.

    
Se aparecer "falso negativo", o tester deixou passar um problema que os testes de referência encontraram.

    
Ao conferir cada teste, o verificador exige os IDs na ordem esperada e as tarefas com seus valores originais. A lista recebida pelo código também precisa continuar intacta.

    
O código roda em um Web Worker, uma execução separada dentro do navegador. Cada conjunto de testes tem um limite de cinco segundos.

  1. Comece pelo spec. Clique em Copiar prompt completo. Prompt é o texto que você envia à IA.
    2. 
    
  2. Abra uma conversa nova no Google AI Studio, envie o texto e cole a resposta de volta no campo do agente.
    3. 
    
  3. Repita com tester e coder, cada um em uma conversa nova. Eles precisam da resposta do spec.
    4. 
    
  4. Para fazer as alterações do seu cenário, edite a instrução e marque quais materiais cada agente deve receber.
    5. 
    
  5. Com as três respostas preenchidas, clique em Montar entrega e levar ao verificador.
    6. 
  

  
Use a mesma comparação entre antes e depois e entregue pelo formulário da sua turma.
